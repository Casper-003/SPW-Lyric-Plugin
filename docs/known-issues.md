# 歌词处理的已知问题

最初的规范化只拆分代码、补齐工程和测试，保留原有歌词行为。下表中的五项问题仍未修复，不应将构建成功或兼容性测试通过视为歌词正确。

## 首句异常处理（1.2.3）

歌曲 `2080448369` 的普通首句在 1.27 秒，YRC 首句却在 4.87 秒，第二句分别为 23.21/23.12 秒。用户已确认关闭逐字歌词后显示正常；此前歌曲信息行又通过时间兜底拿走了首句翻译。

- 制作信息行输出后不再匹配或消费原文/翻译槽位，保留同一时间槽中合并的标题供后续标题行匹配。
- 用前两句有翻译或罗马音的原文建立唯一全文匹配锚点。首句偏差超过 1 秒且第二句偏差不超过 1 秒时，整首降级为普通歌词，不猜测逐字时间；不受显示开关影响。
- 重复文本、缺失辅助歌词或无法唯一匹配时，不据此判断时间异常。此保护不是通用的错误时间轴检测器。
- 合成回归样例保留该歌曲的时间结构。新插件在 SPW 中的显示仍待用户复测。

## 其他已知问题

| 编号 | 已复现的当前行为 | 后续验证方向 |
| --- | --- | --- |
| LYRIC-1 | 前后 5 秒内出现相同歌词时，优先选择时间较早的一条，可能关联错误翻译 | 精确时间优先，再结合距离和前后顺序 |
| LYRIC-2 | 翻译/罗马音和原文必须使用相同时间戳；差 200 ms 就会丢失翻译或变成独立行 | 单独对齐各时间轴，需要歌曲样例验证容差 |
| LYRIC-3 | YRC 行有时间信息但没有有效歌词字时，仍会阻止 LRC 降级 | 识别无效逐字行并验证降级行为 |
| LYRIC-4 | 一行 LRC 中有多个时间标签时，后续标签被当成正文 | 支持重复时间标签，同时验证 SPL 输出 |
| LYRIC-5 | 一行 LRC 对应多行 YRC 时，第一段会消费整个 LRC 槽位 | 确定逻辑行分组和翻译展示策略后再实现 |
