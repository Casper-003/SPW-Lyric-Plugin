# 歌词处理的已知问题

本次变更只拆分代码、补齐工程和测试，保留现有搜索、解析、匹配和 SPL 输出行为。
这里列出的问题尚未修复，不应将构建成功或兼容性测试通过视为歌词正确。

| 编号 | 已复现的当前行为 | 后续验证方向 |
| --- | --- | --- |
| LYRIC-1 | 前后 5 秒内出现相同歌词时，优先选择时间较早的一条，可能关联错误翻译 | 精确时间优先，再结合距离和前后顺序 |
| LYRIC-2 | 翻译/罗马音和原文必须使用相同时间戳；差 200 ms 就会丢失翻译或变成独立行 | 单独对齐各时间轴，需要歌曲样例验证容差 |
| LYRIC-3 | YRC 行有时间信息但没有有效歌词字时，仍会阻止 LRC 降级 | 识别无效逐字行并验证降级行为 |
| LYRIC-4 | 一行 LRC 中有多个时间标签时，后续标签被当成正文 | 支持重复时间标签，同时验证 SPL 输出 |
| LYRIC-5 | 一行 LRC 对应多行 YRC 时，第一段会消费整个 LRC 槽位 | 确定逻辑行分组和翻译展示策略后再实现 |

`LyricCompatibilityTest` 使用旧版已编译插件实际输出的六组数据，锁定本次重构的兼容性，包含上述错误行为。
`KnownLyricIssuesTest` 中的四个测试表达预期修复结果，并以 `@Disabled` 标明原因。这些是跳过的测试，不是通过的测试。
LYRIC-5 的目标展示策略尚未确定，因此只保存当前输出样例，不预先规定修复后的结果。
修复某个问题时，应同时启用对应目标测试、更新明确受影响的兼容性样例，并在 SPW 中验证。

搜索也保留既有行为：只取第一个结果，表单未正确编码特殊字符，括号清洗正则存在问题。
本次仅将请求移入 `NeteaseClient`、清洗移入 `SearchKeyword`，未改变曲目选择策略或端点。
网络响应现在统一使用 `use` 关闭；未改变 HTTP 状态处理规则。

本地播放器验证时，请记录 SPW 版本、准确歌曲版本/网易云 ID、异常时间点、配置开关以及预期显示结果。
离线测试不覆盖 Windows 中的插件加载、真实网易云服务或播放器的 SPL 解析。
